# v2.4.4 免安装版：新版浏览器入口兼容修复

## 本次修复

- 修复新版 CUA 启动参数导致的 `IOException: Unexpected CUA launch entry`，避免浏览器代理配置检查提前停止。
- 兼容新版 `--import require-browser-access.mjs` 加载方式，同时继续支持旧版单脚本入口。
- 仅识别当前已安装插件中的确切本地权限检查脚本。拒绝缺失、替换、远程地址、额外参数等不符合预期的入口；已存在的权限检查脚本不能被静默省略。
- 浏览器代理维护只补齐缺少的 `HTTPS_PROXY`、`NO_PROXY` 转发名称，保留原始参数、浏览器访问授权变量和权限检查文件，并保留回滚备份。

**本次没有关闭或绕过浏览器权限检查。** 该错误表示旧启动器未识别新版入口，本身不等于聊天代理已断开；修复后可以继续执行浏览器代理检查与维护。

## 验证

本地通过 61 项浏览器配置测试，包括新旧入口、错误入口拒绝、字节保留、回滚及并发写入保护；通过 49 项免安装资源检查，以及启动等待、WebSocket 环境备份和托盘会话回归检查。实机配置检查和代理转发修复通过，权限检查文件与访问授权变量保持原样。

验证范围是启动器检查与配置维护，不代表已验证所有网站的浏览器操作，也不承诺消除上游网络故障。

## 使用

下载 `LaunchDeck.exe`，完全退出旧客户端和托盘中的旧启动器，再从新版启动。当前已运行的旧启动器需要正常重启才能使用新检查逻辑。

仍为单 EXE 免安装版：默认增强代理，无需勾选，不包含主题功能。保留浏览器修复、托盘保活及启动诊断。首次准备受保护组件和启用驱动仍需 Windows 授权；不修改系统代理、DNS、FlClash、TUN 或客户端 ASAR / JS。

下载页同时提供 `LaunchDeck.exe.sha256`。详见 [免安装说明](../portable.md) 和 [技术修复记录](../cua-guard-entry-20261029.md)。
